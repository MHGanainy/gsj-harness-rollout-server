# ADR-0002 — The ownership boundary of the moved components

## Context

CP-01 moves the Polar-independent components from the frozen predecessor
(`gsj-envloader` @ v0.8.0). CP-00's report flagged that raw tree sizes and
own-code sizes diverge wildly — `mcp-service/` measured at CP-01: **1.1 GB /
11,448,915 raw lines against 3,463 committed lines** (26 files). The gap is
entirely gitignored artifacts, confirmed by `git status --ignored`: a 1.1 GB
`.venv/` (37,632 files), two `__pycache__` trees (~320 KB), and the 976 KB
`tests/.corpus-bares/` cache the suite regenerates on demand. A boundary
must be stated before anything is copied, or the copy imports environments
and live-estate data it must never own.

## Decision

**The rule: committed source and specifications move; generated artifacts,
environments, and live-estate data do not** — with one stated exception for
the corpus freeze records. "Committed" is decided by `git ls-files` at
v0.8.0, and the copy mechanism is `git archive v0.8.0` (reads the frozen
repo, writes nothing to it — law 3), so nothing untracked can travel by
accident.

Per component:

**`corpus/` → `corpus/`** — comes: `ingest_corpus.py` (1,292 lines), the
four test modules + conftest (625 lines), and the whole staging source tree
`corpus/staging/` (corpus.yaml, AGENTS.md, 2 skills, 4 cases × 3 timesteps,
145 pages, 12 prompts.yaml — 161 data files, 163 with the two freeze
records below). Does not come: the two
`__pycache__/` trees (the only non-committed content).
**The exception**: `corpus/staging/corpus.lock.json` (144 lines) and
`corpus/staging/taskbank.parquet` (3.6 KB, 12 rows) are generated by the
pipeline but come **as committed data**, because (a) they are committed in
the predecessor by the contract's own instruction ("Commit it with the
corpus; it is the freeze record downstream consumers pin against"), (b)
they are deterministic (fixed git identity/date, no timestamps — an
unchanged tree reproduces them byte-identically), and (c) they are *not*
reproducible here: regenerating the lock requires a scaffold run against a
git host, and regenerating the parquet requires the predecessor library's
taskbank API, which ADR-0003 declines to depend on. They are carried as
frozen reference data; the taskbank *builder* is deferred (ADR-0003).
`derive_g2.py` also reads the lock as its case manifest, so leaving it
behind would break the carried pins tooling.

**`mcp-service/` → `mcp-service/`** — comes: all 25 committed files — the
`gsj_mcp_service` package (11 modules, 1,390 lines), tests (8 files, 1,594
lines, 53 tests), Dockerfile, compose.yml, config.yaml, requirements.txt,
README.md, .gitignore. Does not come: `.venv/` (1.1 GB — recreated from
`requirements.txt` per its README), `data/` (clone cache + vector index —
gitignored, absent on this workstation, live only as the H200 deployment's
volume: live-estate data), `tests/.corpus-bares/` (a deterministic cache
the suite rebuilds through the pipeline's `file://` rail), `__pycache__/`,
and any built image layers. Raw-vs-own: 1.1 GB / ~11.45M lines raw vs
3,463 committed lines — **the gap is artifacts, confirmed**. (CP-00's
~852k-line figure was an underestimate of the same venv; its ~1,038 own
lines approximated the package source, measured now at 1,390.)

**`staging/forgejo/` → `forgejo/`** — comes: `docker-compose.yml` (52),
`up.sh` (57), `down.sh` (23), `create_owner.sh` (50) — 182 lines. Does not
come: `forgejo-data/` (the bind mount holding the live estate's
repositories — absent on this workstation, live on the H200) and the
`.token`/`.token-<owner>` credential files the scripts write (gitignored,
live-estate credentials). The compose project name `gsj-envloader-staging`
is **kept**: it names the live staging estate on the H200, not the repo —
renaming it would strand that estate under a dead project name. The
bind-mount path is re-rooted inside the component (`./forgejo-data`), so a
future bring-up from this repo never reaches outside its own tree;
instance data is disposable by design (deterministic bares, re-pushed by
the pipeline).

**pins / G2 tooling → `pins/`** — comes (6 files): `derive_g2.py` (171
lines, stdlib-only — the byte-substitution derivation), and the captured
evidence the tooling derives from: `system_prompt.captured.txt` (the CP-05
G2 capture, the derivation source), `g6_tail.captured.txt` (the pinned G6
verbatim tail, 41 bytes), `tools.captured.json` (the 11-tool wire roster
G3 hashes), `settings.rendered.json` (the G7 settings text), and
`container/system_prompt.container.derived.txt` (docker-mode G2 singleton
— constant-path mode is verify+copy, so this file is itself the only
record of the in-container capture, and it is the G2 text the CP-04/CP-09
golden-reference comparison will need). Does not come: **the pinned
values** — `pins.dev.json` and `pins.staging.json` are generated approved
sets (`format: gsj-pins/1`, gsj-pin output) whose G2 entries embed the
predecessor's host path schemes (`/home/sysadmin/gsj-ep-cp19/...`,
`/workspace` under the predecessor's mounts) and whose provenance records
devharness-era paths that no longer exist; Polar's mounts will change
every G2 hash on day one (CP-00's finding), so carrying the values would
carry data that is stale by construction. Also not coming: the four
`h200/system_prompt.case_000N.derived.txt` files (pure substitution
products, regenerable byte-identically from the captured source with
`derive_g2.py --work-root /home/sysadmin/gsj-ep-cp19`), and
`pins.config.yaml`/`pins.config.staging.yaml` (probe configs for the
`gsj-pin` generator, which is predecessor **library** code
(`gsj/envloader/pin.py`) and stays frozen there; the configs additionally
embed this workstation's absolute HF-cache paths). The approved-set
*format* and the four hashing conventions are specified in
`docs/checks-spec.md`; a successor pin config is written when `checks.py`
exists and Polar's mount scheme is known (CP-07/CP-10/CP-11). This leaves
a deliberate gap — no valid approved-set values exist in this repo until
the re-derive walk — recorded in gap register row 23.

**`docs/corpus-contract.md` → `docs/corpus-contract.md`** — comes as-is,
byte-identical (309 lines). It is the data-prep team's self-contained
specification; measured at CP-01 it contains zero mentions of the
predecessor's library API. Polar-independent by construction.

One consequence inside the copied evidence: the captured G2 texts embed
predecessor host paths (`/home/sysadmin/gsj-envloader/...`) **by nature**
— they are byte-load-bearing hash inputs and are exempt from path
reconciliation; rewriting them would poison every hash derived from them.

## Consequence

These components are now **maintained here** — the charter's carried-over
table says so, and fixes to them happen in this repo (A-9). The
predecessor's copies stay untouched and frozen (law 3); nothing about this
move changes `gsj-envloader` @ v0.8.0, which remains the fallback and the
golden reference. Environments left behind are recreated locally
(`mcp-service/.venv` from its README recipe); live-estate data and
credentials are never copied, only re-created by running the bring-up
against a host. The pinned-values gap is deliberate and cured by the
derive → re-pin → first-episode-validate walk once Polar's mount scheme
exists.
