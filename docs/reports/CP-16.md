### The bridge's conversion table (Step 3)

Callback-shaped mapping → slime `Sample` (v0.3.0 surface, read from the
vendored adapter — not invented):

| Trace/body field | Sample field | Rule |
| --- | --- | --- |
| `prompt_ids + response_ids` | `tokens` | concatenation, ids verbatim, never retokenized |
| `len(response_ids)` | `response_length` | — |
| `loss_mask` | `loss_mask` | builder's mask verbatim (never inferred); absent → all-zero; zeroed wholesale on ABORTED/FAILED/findings |
| `response_logprobs` | `rollout_log_probs` | behaviour-policy values, asserted (below); `[0.0]*n` only on inert paths |
| `reward` | `reward = {reward_key: v}` | evaluator's value; `null` → `0.0` (F-02 — real bodies all carry null) |
| `prompt_messages` | `prompt` | deep copy, `""` when empty |
| `response_messages` | `response` | `[role] content` text (lossy, human-readable only — vendored limitation kept) |
| statuses | `status` | `TIMEOUT`→ABORTED · `ERROR`/errors→FAILED · findings→FAILED · `finish_reason=="length"`→TRUNCATED · else COMPLETED |
| — | `group_id = index` | all traces of one trajectory share it (slime 0.3.0 loss reducer counts it once) |
| metadata ×3 | `metadata["polar"]` + scheduler keys | the vendored block; `group_id`/`policy_version`/`rollout_step` forwarded when stamped |
| — | `metadata["gsj"]` | trainer-side findings, pins provenance, masked behaviour aggregates |

Zero-gradient mechanism, named: **zeroed `loss_mask`** for
aborted/failed/findings-bearing samples (kept in batch — group shape

at all becomes one fully-masked **`remove_sample=True`** placeholder
(vendored mechanism kept verbatim, including its hardcoded
`tokens=[0, 0]` — flagged as F-05 rather than silently deviated from).

### The three assertions, with failing-when-removed evidence (Step 4)

Each was neutralized in a scratch edit, the suite run, the named tests
observed red, the edit reverted (final suite 14/14 green, tree clean):

1. **Mask before ratio** (`assert_mask_before_ratio` + the masked-only
   aggregate). Interstitials carry `0.0` ≡ probability 1.0; upstream's
   own statement that masking is the consumer's job is
   `polar/trajectory/builder/prefix_merging.py:366-368` ("Interstitial
   slots (tool results, chat glue) get 0.0; loss_mask=0 makes the
   trainer ignore them"). Enforced two ways: a non-zero logprob at
   mask==0 raises `MaskDisciplineError` (mask/logprob disagreement —
   exactly what an unmasked ratio would consume silently; the discipline
   is real: 100% of mask-0 positions are exactly `0.0` in every fixture
   body), and the only aggregate emitted is computed under the mask.
   Removed → `test_nonzero_logprob_at_masked_position_is_rejected`
   FAILED (1 failed, 13 passed).
2. **Sentinel rejection** (`assert_sentinel_free`, the bridge's own
   `-9000.0` floor — deliberately independent of `CheckPolicy`).
   `-9999.0` is finite and ≤ 0; CP-02: upstream has no value-level
   validation anywhere. Removed →
   `test_sentinel_at_stated_trainable_position_is_rejected` and
   `test_sentinel_is_rejected_even_when_the_policy_was_loosened` FAILED
   (2 failed, 12 passed). The second test is the independence proof: LP3
   disarmed via `CheckPolicy(sentinel_threshold=-1e12)` → checks returns
   clean → only the bridge's assertion stands, and it does.
3. **`checks` runs trainer-side** (`validate_session_result` called in
   `ingest_session_result` — CP-08's recording-wrapper pattern, exactly
   `test_client.py`'s monkeypatch-then-delegate lambda). Removed
   (`findings = []`) → `test_checks_runs_trainer_side_on_what_arrived`,
   `test_unstamped_cp07_body_is_never_trainable`, AND
   `test_timeout_session_contributes_zero_gradient` FAILED (3 failed,
   11 passed) — the unstamped CP-07 body really does fail the gates
   trainer-side (`G1`/`G5`/`G7:missing_evidence`), and removing the call
   silently promotes it to trainable, which is the whole threat.

CP-09′ inheritance: **the bridge does no replay** — replay needs the

### What "demo-purpose" meant concretely in the vendored bridge (Step 3)

- **No value-level logprob validation anywhere**: `_extract_rollout_log_probs`
  checks presence and length only, then `[float(v) for v in logprobs]` —
  a `-9999.0` sentinel, a positive logprob, a NaN all pass into
  `rollout_log_probs` untouched.
- **Interstitial trust by comment**: "interstitials are 0.0, masked out
  by loss_mask; the builder guarantees…" — a guarantee consumed, never
  verified.
- **Consumes Polar's pydantic models** (`result.trajectory.traces`,
  `result.timing.model_dump()`) — the trainer holding only callback JSON
  cannot call it.
- Placeholder hardcodes `tokens=[0, 0]`, `response_length=1` (token id 0
  assumed batcher-safe — kept, flagged F-05); missing reward → `0.0`
  silently in four places (`reward.py` even falls back to "first numeric
  value in the dict"); `policy_version` is just the rollout id — no true
  weights-delta signal; status vocabulary matched by string literal;
  exactly one submit attempt, no retry — a failed group is silently lost
  from the epoch; unauthenticated plain-HTTP callback listener;
  positional `group[pos] ↔ results[pos]` pairing (order assumed, only
  count checked); oversize traces dropped wholesale, never clipped;
  `int(v)` mask coercion (raises on junk, silently coerces 2 → 1).
- One correction to the prompt's framing: it is **not** single-turn-only
  and is sturdier than "demo" suggests in places (length mismatches
  raise, per-category drop metrics, callback+poll redundancy) — the real
  fragilities are the ones listed.

### What our traces don't fit about slime's expected shape (Step 6, report ask)

- **`reward: null` on every real body** (CP-06/07/09/09′) — slime's
  `Sample.reward` wants a value; the bridge writes `{key: 0.0}` and
  F-02 names the attach step as CP-17's. A loop run today trains on
  zero reward everywhere.
- **`policy_version`/`rollout_step` never stamped** — the vendored
  staleness machinery keys on them; P3 inert until a trainer declares
  versions (A-13).
- **`session_id=` and `Status.FAILED` on the Sample constructor** are
  verified only against the vendored adapter's own usage — real slime
  v0.3.0 (+ router-tokens patch) can only confirm on-estate (A-26,
  F-04). No misfit *observed*; the observation surface doesn't exist
  here.
- Everything else fits: per-response-token mask/logprob arrays, verbatim
  token ids, multi-trace grouping — the fixtures converted without a
  single shape workaround.
