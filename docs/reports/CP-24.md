#### The row shape, field by field (ADR-0022 §1)

One row per `(case, timestep, prompt)`, flat, eight columns, sorted
`(case_id, timestep, prompt_id)`:

| column | why |
| --- | --- |
| `case_id` / `timestep` / `prompt_id` | the triple — the enumeration a consumer exists to read; the first two are `render_task_request` arguments, the third joins back to the tree and names the ask |
| `split` | ADR-0015's row-spec verbatim: case-level, from `lock.cases.<id>.split`, passed to `render_task_request(split=…)` |
| `prompt_source` | the exact render value (`free` \| `skill:<name>`) — carried so no consumer re-derives it from `prompt_id` |
| `prompt_text` | free rows: the contract's verbatim text — the instruction; null on skill rows |
| `skill_card_text` | skill rows: the **resolved** corpus-level card (raw file bytes decoded UTF-8, CP-13's binding constraint) — `render_task_request(skill_card_text=…)` and the instruction; null on free rows |
| `sandbox_image` | corpus-level constant per row — contract v2 already promised it; predecessor parity |

Dropped from the predecessor's §3.1, each with its reason in the ADR:
`data_source` (keys the dropped loader's registry), the chat-message
`prompt` list (the loader's chat shape; our surface takes an instruction
string), the `extra_info.tools_kwargs…` nesting (runtime/agent settings
come from the one YAML, never a row).

#### Skill resolution: the bank carries the resolved text (ADR-0022 §2)

Not the hash (render computes it — one arithmetic, nothing downstream
trusts a caller's), not a reference (the row would not submit without
translation), not nothing (G1 would fail closed with no honest source
for the statement). The chain this buys G1, whole: corpus card bytes →
bank `skill_card_text` → render-computed `skill_card_hash` →
`TaskRequest.metadata` → trace metadata (the CP-11 hoist) →
`check_skill_card` ∈ the pinned set. The limit stays named: this is
build-time resolution of the corpus-level card — a drifted *checkout* is
wishlist 9's territory, unchanged in kind; a card edited after a build
is a named `verify` FAIL (`skill_card_text != the tree's bytes`,
test-pinned).
