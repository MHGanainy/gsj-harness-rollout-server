#### The comparison contract's decisions (Step 5)

- **Not greedy — measured, not chosen.** Greedy was the first choice and
  was abandoned on evidence: under `temperature 0.0` the model's first
  assistant turn falls into an infinite `<tool_call>` emission loop
  (uncapped: >25k tokens, wall-timeout; capped: exactly 8192, `length`,
  zero tool executions). The loop lives in the sampling-independent part
  of the context, so retries and other triples reproduce it. Both runs
  therefore use the reference block; pi sends no sampling params, so CP-09
  must confirm its engine applies the identical generation-config defaults
  and record the mechanism.
- **What stays token-exact**: `prompt_ids` (sampling-independent rendered
  context) and the interstitial glue spans (template constants). Sampled
  ids are compared per-trace by decode-fidelity, never across traces.
- **Masks**: zero tolerance, per trace — mask==1 exactly on
  engine-sampled spans, boundaries aligned to turn structure; the
  comparison that matters most.
- **Logprobs**: discipline both sides (finite, ≤0, no sentinel, `0.0`
  only at mask==0) + a **replay check** — teacher-force the frozen
  `input_ids` through the same engine and compare within mean|Δ| ≤ 0.005,
  per-position |Δ| ≤ 0.05 (anchored to the predecessor's CP-18 measured
  0.0036 drift).
- **Structural mapping**: `prompts ↔ prompt_ids`, `responses ↔
  response_ids`, `loss_mask ↔ loss_mask`; the golden's `input_ids =
  prompts + responses` and `loss_mask == response_mask` identities are
  freeze-asserted so the mapping is total.
- Mismatch attribution is written per field (ours / Polar's / the
  platform's), with the A-1 retokenization breach and mask-semantics
  divergence named as the Polar-fault classes (the first is an
  abandonment trigger).

#### What surprised us about the predecessor's stack off its home platform

1. **The context-window/max-model-len coupling fails ugly**: the session
   sizes per-turn `max_tokens` from `context_window`; an engine with a
   smaller `max_model_len` rejects every call 400, pi retries into empty
   `stop: error` turns, and the episode ends `completed`/gates-green with
   zero completions and `uid: null` — nine such attempts before diagnosis.
   The loud part lived in the trainability layer (0 trainable), not the
   gates. Echoes the H-41 lesson from a new direction.
2. **Greedy is uncollectible for Qwen3-0.6B on this task family** — the
   comparison contract had to be redesigned around it (the CP prompt's
   "under greedy they should be [identical]" presumed a collectible greedy
   run; the presumption is false for this model).
3. **MLX bf16 emits exact-`0.0` sampled logprobs** (20/292 on the frozen
   episode) — legal per the CP's assertions, fatal per the checks-spec
   suspicious-zero rule; row 27 now carries the platform-conditioning
   question for CP-10.
4. **A `truncated` episode satisfies the collector's `episodes=1` target**
   ("new trainable" counts it; only the loader's `ready` predicate
   filters) — surprising semantics worth pinning down when CP-08 exposes
   "collect N" (gap row 26).
5. **The pins are estate-invariant under docker execution** — the G2
   "path-sensitivity" everyone (this CP's prompt included) braced for is a
   subprocess-mode property; docker-mode episodes carry the `/workspace`
   singleton, and the whole pins file reproduced byte-value-identical on
   a machine it was never generated on. The Mac estate consumed the frozen
   H200 pins unchanged.
6. **Everything else just worked**: the amd64 pi image under emulation,
   `host.docker.internal` from Docker Desktop, the scaffolder reproducing
   frozen SHAs on macOS, `push_inputs.sh` converging to the same
   deterministic commit (`f9ba24ac…`), and the driver's loopback→
   `host.docker.internal` rewrite — zero predecessor code changes end to
   end (law 3 held without strain).
