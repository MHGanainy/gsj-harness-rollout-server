## The buffering decision

**Flush, not a durable file**: `flush=True` on all six serve-session
prints. Once flushed, the nohup log itself is the durable record — the
CP-26 scenario re-run verbatim (`nohup python -m gsj_rollout.cli serve … >
log &`) now shows the topology path, both Polar commands (absolute), the
callbacks line, and `receiver listening` in the log while the server
runs. A separate commands file would be a second artifact to go stale;
`topology.rendered.yaml` already persists the rendered half.
