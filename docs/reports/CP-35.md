## Notes

### Step 1 — what a 587 KB archived body actually contains

CP-34's accepted episode (`sk-polar-e04cc98c….thinking-off.json`,
586,643 bytes), read before anything was designed:

- **Top level** (8 keys): session_id, task_id, status, trajectory,
  timing (4 phase durations), node_id, error, metadata (the task:
  case_mill, timestep 3, skill:brief, eval, card hash).
- **trajectory.metadata**: builder, api_type, model requested/used,
  record_count 71, reconstruction_stats (1 chain, full, 71/71 merged),
  completion_filter (0 excluded), gsj_validation (0 findings).
- **traces[0]** (10 keys): `prompt_ids` 2,920 · `response_ids` 25,949 ·
  `loss_mask` 25,949 (2,569 ones = 9.9%) · `response_logprobs` 25,949
  (0.0 at every mask-0 position, real at mask-1) · `prompt_messages` 2
  (system 4,466 chars sha `f56e8a6e…`; user, typed-parts) ·
  `response_messages` 141 (assistant/tool alternating, OpenAI shapes,
  null-field noise) · `tools` 11 · `finish_reason` "length" · `reward`
  null · metadata (gsj_workspace with the **page census** {count 3,
  min 1, max 3} + 71 completion_metadata copies).
- The four arrays are **~95% of the bytes**. What the episode DID: read
  `/workspace/AGENTS.md` seventy times and truncated mid-tool-call (the
  last assistant message is the string `"<tool_call>"`).

**The finding that decided the design**: the archive's MESSAGES lose
thinking-on reasoning. vLLM's `--reasoning-parser` strips `<think>` from
`content` into `reasoning_content`; Polar's capture has a `reasoning`
field (different name) — null in all 156 bodies measured (153 CP-32
archives + CP-34's + CP-35's two). Reasoning survives ONLY in the token
arrays, so rendering it means decoding the k-th contiguous mask-1 run as
turn k — an alignment measured exact on every body (A-29), and the
reader REFUSES rather than guesses when it breaks. Wishlist 39 is the
message-side cure.

### What each view carries, and what it leaves out

**`show` (the transcript)** carries: the task triple + checkout (branch,
pages visible at the cutoff), status/model/turn/token/mask counts,
finish_reason with the ADR-0025 sentence when `length`, the system
prompt as **hash + size** (4,466 chars of pinned boilerplate is not
reading material), the user prompt verbatim, then per turn: decoded
thinking (`| `-prefixed), tool calls with args, results — MCP search
hits parsed to per-hit `page N / score / file` lines **with an
on-the-spot cutoff verdict** ("all <= timestep 3 (the cutoff holds)") —
assistant text, and at the end the deliverable in full or the explicit
"NO deliverable was written". Leaves out: the token arrays, the
logprobs, the tool-definition roster, the message-object null noise,
and literal repetition (runs of ≥3 byte-identical turns collapse to one
block with an honest count — the CP-34 episode is the motivating case).

**`export` (the projection)** carries: archive {path, disposition,
pins_mode from the F-48 stamp}, session, task, model, gate_findings,
gsj_validation, reconstruction_stats, completion_filter, timing,
workspace, finish_reason, reward, counts (prompt/response/trainable
tokens + share, turns, tool_calls, think_tokens with its stated basis),
page_census (timestep, workspace pages, distinct search pages returned,
pages-beyond-timestep — should always be empty; a program can verify),
turns[] (n, content, calls name+args verbatim, results as {chars,
head-200}, token_span = the turn's mask-1 run), and **arrays
REFERENCED**: `{included: false, where: <path → pointer>, why}`.
Decision: referenced by default because they are ~95% of the bytes and
the archive holds them verbatim — measured 43,978-byte export against
the 586,643-byte body; `--arrays` embeds them for a consumer who wants
one self-contained file. Leaves out: full tool-result text (chars+head;
the archive has the rest).

```
[ ok ] model             'Qwen/Qwen3-0.6B' is served
[ ok ] context window    max_model_len 32,768 >= the harness's planning window 32,768
[ ok ] tool parser       the endpoint returned a structured tool_call for a tool-begging prompt
[ ok ] tokenizer tail    /tokenize renders the pinned G6 tail exactly ([151644, 77091, 198, 151667, 271, 151668, 271])
[ ok ] end-of-turn id    '<|im_end|>' -> [151645] — matches the builder's pin
[warn] sampling defaults NOT PROBEABLE over the API. […]
```

CAN see: reachability (an HTTP error status is a FAIL naming the
/v1-suffix trap, not a pass); the served name byte-for-byte; the stated
window (vLLM's `max_model_len`; honestly a warn when unstated); whether
tools come back structured (a real completion with a tool-begging
prompt; text-instead-of-calls is a warn, a 4xx on the tools param a
FAIL); and — the real win — the served TOKENIZER against this estate's
pinned tail ids and EOT id via vLLM's `/tokenize`, which converts "your
first episode will quarantine at G6" into a named preflight FAIL with
the consequence stated. CANNOT see: sampling defaults (no OpenAI-compat
surface states them — said once, out loud, with the T=1.0 consequence
and the server-side fix; wishlist 38), non-vLLM tokenizers (`/tokenize`
absent → the warn says the G6 quarantine is where it would surface),
and container-side reachability (bootstrap's engine line owns that
path). Known accepted limit: the probe timeouts bound socket waits, not
a byte-trickling server.
