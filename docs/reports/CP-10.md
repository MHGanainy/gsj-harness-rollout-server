#### Step 1 — the logprob discipline, as landed

Eleven rules, all inside `run_trace_checks`, so both legs of law 6 get
them identically — the receiver on the POSTed body, the client on what it
fetched. Thresholds live on a frozen `CheckPolicy` dataclass with the
reasoning in its docstring.

| id | rule | threshold / note |
|---|---|---|
| `LP1:response_logprobs_absent` | null/absent array on a trainable trace | trainable = any `mask == 1` |
| `LP2:response_logprobs_length_ne_response_ids` | length ≠ `len(response_ids)` | detail `{got}!={want}` |
| `LP3:sentinel_logprob_at_mask1` | logprob ≤ threshold at `mask == 1` | **−9000.0** |
| `LP4:nonfinite_logprob` | NaN/±inf or non-numeric, anywhere | Python's `json` accepts `NaN`/`Infinity` off the wire |
| `LP5:positive_logprob` | value > 0, anywhere | |
| `LP6:zero_logprob_rate_at_mask1` | exact-`0.0` share of `mask == 1` above the allowance | **0.25**, platform-conditioned |
| `LP7:empty_loss_mask` | empty mask, non-empty `response_ids` | the `models.py:116` validator escape |
| `LP8:loss_mask_length_ne_response_ids` | mask length ≠ `len(response_ids)` | |
| `LP9:loss_mask_value_not_binary` | any mask entry that is not int `0`/`1` | **the rule the other mask-keyed rules depend on** — added after the adversarial pass, see §Verification |
| `TR1:finish_reason_not_allowed` | ∉ `{stop, tool_calls, stop_sequence, length}` | tail aborts |
| `TR2:reasoning_loss_mask_masked_tokens` | `reasoning_loss_mask.masked_tokens` is anything but a recognized zero | re-vendor canary, deliberately not type-narrowed |

Why the sentinel rule is a *threshold* and not a consequence of
finite-and-≤0: `-9999.0` is finite, ≤ 0 and not `0.0`, so the naive
discipline admits it — the spec's own correction at CP-02. It is
load-bearing rather than duplicative because CP-02/CP-05 established, by
grep over the whole vendored tree, that **nothing upstream value-checks a
logprob anywhere**; the slime adapter checks presence and length only.
Accepted false-positive surface, unchanged from the spec: a genuine
ultra-low logprob clamped to the floor is indistinguishable from a
missing one — degenerate either way.

Raw semantics are respected literally: **no renormalization transform
appears anywhere in the discipline math**, because CP-09 measured the raw
hypothesis replaying at the platform numerics floor while the
sampling-renormalized hypothesis fit ~6× worse, on both stacks.

#### The platform-conditioning decision, and the numbers behind it

Row 27's rule as originally specced — *any* `0.0` at `mask == 1` fails —
would have rejected **both** reference traces this repo owns:

| trace | `mask == 1` | exact `0.0` at `mask == 1` | share |
|---|---|---|---|
| predecessor's golden (`docs/golden/mac/tokens.npz`) | 292 | 20 | 6.8% |
| Polar's collected (`docs/polar/fidelity/trace.json`) | 363 | 15 | 4.1% |
| CP-07's corpus episode (`docs/polar/pi-corpus/…`) | 441 | 27 | 6.1% |

All three are otherwise discipline-clean, and CP-09 attributed the
artifact: bf16 rounding of genuinely-near-zero RAW logprobs. So the rule
landed as an **allowance**, `CheckPolicy.zero_at_mask1_max_rate`, default
**0.25** — ~3.6× the highest measurement. No measured trace trips it; a
degenerate array does (`LP6:zero_logprob_rate_at_mask1:363/363>0.25`).
Setting it to `0.0` restores the original strictness exactly, which is
what a CUDA estate should do:

```
strict policy (rate 0.0), CP-09 trace   -> ['LP6:zero_logprob_rate_at_mask1:15/363>0.0']
strict policy (rate 0.0), golden tokens -> ['LP6:zero_logprob_rate_at_mask1:20/292>0.0']
```

It is a **knob rather than an engine sniff** for a reason recorded at
CP-09 (row 22): the trace carries no engine identity at all — sampling
and engine provenance are estate provenance, not trace provenance. A rule
that tried to detect "am I on MLX?" from the trace would be inventing
evidence. What is *not* lost: Polar's `0.0` placeholder can never reach
`mask == 1` (`prefix_merging.py:364,368` nulls the whole array first), so
every zero the rule counts is genuinely engine-reported.

#### Step 2 — G5, the cutoff

`checks.check_page_cutoff`. The census is reconstructed from the trace's
own `prompt_messages` + `response_messages`: tool names ride the assistant
turn's `tool_calls[].function.name` and results carry only
`tool_call_id`, so names are resolved by id across the merged multi-turn
stream. Both spec regexes are used — `"page"\s*:\s*(\d+)` and
`md/page_(\d{4})\.md` — the compatibility contract with the MCP service's
result shape. The filter is `mcp_gsj_search_case` only: decisions results
are cutoff-exempt (the predecessor's ADR-0007(e)), and a built-in `read`
of `md/page_0007.md` cites the checkout, which the `timestep-{T}` clone
already clamps. Both exemptions are tested with the same page number that
fails through `search_case`, so the filter is proven to be the thing doing
the work.

**T comes from the trace, never from a caller.** Precedence:
`metadata.timestep`, then `metadata.task_metadata.timestep`, then the
`mcp_gsj_case_status` result's own `"timestep"`. Here is the honest part:
the CP says "the harness settings ride through" — **they do not**. The
CP-09 callback's trace metadata carries `session_id`, `task_id` and
`completion_metadata` and nothing else; the harness settings stop at the
`AgentSpec`. So today T reaches the check only through the third source —
the MCP service stating, from the same verified token claims that drive
the clamp, which timestep this episode is scoped to. That is strictly
weaker than metadata (a service lying about both T and its pages defeats
it) and it is the reason the row stays GAP. The structural fix is one
line in `config.py:render_task_request` (put the timestep in
`TaskRequest.metadata`), which is frozen this CP and is CP-11's first
item. With neither source the gate fails closed —
`G5:missing_evidence:timestep` — per the spec's posture that evidence
never gathered fails its owning gate, which does mean an episode whose
agent never calls `case_status` is rejected until that line lands.

Framed as the spec requires: **this is the backstop, not the
enforcement.** The clamp is server-side and was proven at CP-07, tamper
probe and all. This catches a service that misbehaved or a result shape
that changed under us.

Two clauses of the predecessor's G5 did **not** land, and were not faked:
max checkout page == T, and checkout pages contiguous from 1. Both need
the *checkout* census — a property of the sandbox filesystem that appears
nowhere in the trace. What backstopped them here is the `timestep-{T}`
branch clone itself. On CP-11's list to either drop with a note or source
from a harness-recorded probe. The §9 abandonment trigger ("G5 is
unreconstructable from the trace") is **not** touched: the search-page
census, which is the clause that guards what the agent actually saw, is
fully reconstructable and now enforced.

#### Was replay implemented? No — deliberately, and here is the record

Not built, per the CP's own recommendation, and the reasons are now in
`docs/checks-spec.md` §Replay so a later CP re-opens it on evidence: it
needs an engine that neither side of the wire has; it **cannot run at all**
on Mac estates (F3 — vllm-metal hardcodes `prompt_logprobs_dict={}` and
the `echo` path 500s); its tolerance anchor does not transfer (F4 — the
0.005/0.05 bounds are the predecessor's same-engine measurement, the
beside-the-engine floor is 0.007–0.016 on both stacks symmetrically); and
on a multi-turn trace **the check itself could be wrong** (F2 — it must
de-stitch the ADR-0007 glue first, and that identity is session-specific,
not structural). If one is ever built the binding rules are recorded:
de-stitch via the config-pinned `generation_prompt_glue_ids`, re-render
and calibrate rather than assume, and prefer capture-vs-capture on
identical contexts (CP-09: mean |Δ| = 0.000114), which needs no tolerance
re-anchoring.

#### Verification

Beyond the suite, the landed rules were put through a six-agent
adversarial pass (five refutation lenses — spec conformance, fail-open
hunting, false-rejection hunting, G5 against the real MCP service's result
shapes, and measurement re-derivation plus scope compliance — followed by
a fresh-eyes completeness critic over their raw findings). Every agent was
instructed to refute rather than confirm, and to substantiate with a
citation or an executed command. Results and dispositions:

**One blocking defect in my own first implementation, confirmed and
fixed.** The `loss_mask` value domain was never validated, and every other
mask-keyed rule tests `flag == 1` — which is `False` for `"1"`, `2`,
`1.0`-as-string and JSON `NaN`. So a mask stringified by a serializer bug,
or supplied by a hostile payload on either wire leg, made **`LP1`, `LP3`
and `LP6` simultaneously vacuous**: the critic executed the real CP-07
callback body with its mask retyped to strings and its logprobs replaced
by all `-9999.0`, and `validate_session_result` returned `[]` — accepted.
`LP7`/`LP8` were blind because the mask was neither empty nor mis-sized.
Fixed by `LP9:loss_mask_value_not_binary` (the mask is 0/1 ints or it is
not evidence), tested across `"1"`, `2`, `NaN`, `None` and `True` — the
bool case correctly fires `LP9` *and* `LP3`, since `True == 1` in Python.
This is the strongest argument for the pass: the rule that closes it
would not have existed otherwise.

**Two more real defects, both fixed.** `TR2` was type-narrowed to `int`,
so a `masked_tokens` of `3.0` or `"3"` passed silently — a canary for an
*unknown* future change must not assume the encoding that change will use;
it now fires on anything that is not a recognized zero. And
`_content_text` read a bare part mapping or a list of plain strings as
empty text, which is precisely how a census goes silently blind; it now
accepts every envelope it can recognize, tested across four shapes.

**One finding that is not about `checks.py` at all, and is the most
important thing this checkpoint produced.** Verifying G5 against the real
service surfaced a **cutoff channel no trace-side check can see**: each
`timestep-{T}` branch is one truncation commit on top of `main`'s
full-document commit (`corpus/ingest_corpus.py:601-612`), the harness
clones `--branch … --single-branch` with **no `--depth`**
(`pi_harness.py:127`), and `bash` is on the measured wire roster — so
`git show HEAD~1:md/page_0018.md` returns a post-cutoff page from inside
the sandbox, offline, without touching the MCP service. I reproduced it
end to end with the exact ingest recipe and clone flags before recording
it. Attribution, stated honestly: **inherited, not introduced** — the
predecessor clones the *whole* repository, every branch
(`task.py:826-839`), so its exposure is wider and row 2's PARITY claim
survives; what does not survive is §5's "nothing past page T visible
through any channel", on either stack. G5 is blind to it by construction
(the leak is `bash` output, not an `mcp_gsj_*` result — the same scoping
that makes the decisions exemption correct). The fix is one flag,
`--depth 1` plus dropping the `origin` remote, at the next
`pi_harness.py` freeze-lift. Recorded in gap row 2, in §5, and on the
inherited list; **not** fixed here, because `pi_harness.py` and `corpus/`
are frozen this CP.

**Recorded, not fixed** (each with its reason): `CheckPolicy` has no
operator surface — receiver and client call with defaults and `config.py`
is frozen, so "a CUDA estate sets it to `0.0`" has no mechanism yet
(inherited list item 7); `mcp-service/README.md` still points auditors at
"CP-11" for regexes that landed at CP-10 (item 8, component frozen); G5's
remaining census blind spots — quoted page values, unresolvable
`tool_call_id`s, duplicate ids — now enumerated in the spec so a shape
change is recognized rather than rediscovered; and the spec's superseded
hard-fail bullet now carries an inline correction marker, matching the
CP-02/CP-05 precedent, so nobody re-implements the rule that rejects every
MLX trace. A docstring in `tests/conftest.py` attributed the golden's
`finish_reason` to its MANIFEST; the value is right but the provenance is
`record.json` → `env.steps[*].stop_reason` (verified: `['stop', 'stop']`),
and the citation is corrected.

**Dispositioned as noise** by the critic, and I agree after checking each:
the G5 timestep circularity and the optional-`case_status` rejection risk
(both documented verbatim in the code, the spec and row 13 before the pass
ran); regex blindness to quoted page values (the declared compatibility
contract); non-search channels being census-exempt (the documented scope
decision); `LP1`'s mask-derived trainability (it matches the pin's actual
mechanism — upstream raises only when a `mask == 1` slot lacks a logprob);
and tokenless/empty-array traces passing (G6/G7's job, explicitly deferred
by the STOP wall). The measurements lens returned **CONFIRMED_SOUND** on
