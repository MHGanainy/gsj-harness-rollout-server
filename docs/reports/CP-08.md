#### The four surfaces as landed (ADR-0008)

**`config.py` (241 lines)** — one YAML, and it GENERATES Polar's surfaces.
Seven library sections (`estate`, `runtime`, `harness`, `builder`,
`polar`, `receiver`, and root), all `extra="forbid"` with unknown keys
raising "section 'x': unknown key 'y'", plus the reserved free-form
`user:` mapping the library validates and never reads (tested: arbitrary
nested keys load and never appear in any render). `render_topology(cfg)`
→ Polar's `topology.yaml`; `render_task_request(cfg, task triple…)` →
one `TaskRequest` body with `callback_url` pointed at our receiver.
Both renders are golden-file-tested AND validated against Polar's own
`TopologyConfig`/`TaskRequest` pydantic models from `vendor/polar/.venv`
— CP-09 inherits a construction surface that Polar itself has already
accepted. `runtime.workdir` is unrepresentable by design (the CP-06
trap); `backend` is a value (law 5 — `apptainer` is a YAML edit away).

**`receiver.py` (143 lines)** — validates the POSTed body, never rollout
disk. `POST /callbacks/session_result` accepts a single `SessionResult`
(the fixture's contract) or the manager's `TaskResult` envelope,
unwrapped per member; every result runs
`checks.validate_session_result`; accepted → persisted **verbatim**
(status/error intact) at `<traces_dir>/<session_id>.json`; rejected →
`<quarantine_dir>/<session_id>.json` carrying `{findings,
session_result}`. Polar gets 200 `{"accepted": n, "rejected": m}` either
way (rejection is our decision, not a delivery failure — a non-2xx only
triggers the manager's spurious "fall back to polling" warning); 400 for
malformed shapes, including traversal-shaped session ids (they become
filenames). Stdlib HTTP; no signal handlers at import.

**`client.py` (123 lines)** — `RolloutClient.submit/wait/collect` +
`Trace` (our pydantic mirror; `polar` is never imported).
Polls `GET /rollout/task/{id}` — NOT the receiver's disk — because the
poll returns the callback-validated bodies verbatim with status intact
(the fixture's own provenance), the trainer need not share a disk, and
law 6 wants this side's verdict independent. Rejected sessions are
reported (log line with findings), never returned.

**`cli.py` (175 lines)** — `serve` renders `topology.rendered.yaml`,
prints the two Polar commands (`polar serve_rollout|serve_gateway` with
PYTHONPATH and the token-secret env reminder), starts the receiver, and
owns SIGINT/SIGTERM only for its own lifetime (installed inside
`serve()`, tested absent at import). `submit` renders the task request
from config + `(--case, --timestep, --prompt|--prompt-file,
--episodes)`, waits bounded (`--timeout` + `--grace`), prints one
progress line per state change, re-checks client-side, writes `--out`,
exits 0/1/2/3 as stated.

#### Collect-N semantics as written (row 26 closed)

Stated once in `config.py` (`COLLECT_SEMANTICS`, appended to the module
docstring) and printed verbatim in `submit --help`: collected =
`COMPLETED` ∧ no builder findings ∧ no checks findings (ERROR/TIMEOUT
never count); `--episodes N` = N **attempts** (`num_samples=N`), not
collect-until-N-accepted; a rejected trace is a consumed attempt,
quarantined, never auto-retried; exit 1 = collected < attempted. The
predecessor's `truncated`-counts ambiguity has no analogue by
construction: the CP-07 builder flips truncation-class defects to ERROR.

#### The adversarial review and what it forced

A 4-dimension × 2-refuter review workflow (50 agents) over the diff:
23 raw findings, 12 refuted, 11 confirmed — all fixed and re-tested:
(1) **the seam's never-raises contract was violable** (critical):
truthy non-mapping `trajectory`/`metadata`/`traces` content crashed
`validate_session_result` (an `AttributeError` past the `or {}`
re-fetch), killing the receiver's handler thread with no response and
crashing `collect()` client-side — hardened with mapping guards +
`ADM5:malformed_trace`, tested over HTTP and in-process; (2) malformed
YAML raised `yaml.YAMLError` past `except (OSError, ValueError)` —
mapped to the stated exit 2; (3) a reachable-but-erroring rollout server
(4xx/5xx) crashed `submit` — now `httpx.HTTPError` → exit 3; (4)
`__doc__ += …` broke under `python -OO`; (5) `collect()` silently
discarded rejections, contradicting ADR-0008 §3's "reported, never
returned" — now logged with findings; (6–11) mutation-proven test gaps
(mixed envelope, submit's exit-1 path, `wait`'s `TimeoutError`, the HTTP
error path, seam wiring) — each now pinned by a test. Two stdlib traps
worth recording: `BaseServer.shutdown()` deadlocks unless
`serve_forever` is running (a serve-thread guard now covers it), and
`session_id` reaching the filesystem as a filename is screened
(`_SAFE_SESSION_ID`).

#### What the real callback body forced that the design didn't anticipate

The body itself validated as designed — the surprise was the **channel**:
the per-session `SessionResult` push cannot reach us zero-patch (the
pipeline pins the node's callback to Polar's own rollout server), so the
live push is the manager's **task-terminal** `TaskResult` envelope and
per-session immediacy would need a vendored patch (row 28 finding; the
client's poll path is unaffected and is what `submit` uses). Everything
else the design absorbed: the envelope unwraps into the same admission
path the fixture exercises.
