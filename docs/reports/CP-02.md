#### What this changes about `checks.py`'s job

1. **The sentinel guard was mis-specified** — corrected: an explicit
   "`mask==1` logprob ≤ −9000.0 fails" rule (the finite-and-≤0 rule
   passes `-9999.0`). Upstream has NO value-level logprob validation, so
   our guard is load-bearing, not duplicative.
2. **New rules added to the spec:** `response_logprobs` absent/None on a
   trainable trace fails hard (upstream's rejection is config-gated —
   don't inherit); `finish_reason` allowlist
   `{stop, tool_calls, stop_sequence, length}` (catches tail aborts);
   `reasoning_loss_mask.masked_tokens > 0` fails (re-vendor canary).
3. **G7 verified implementable receiver-side** via the pin's
   `reconstruction_stats` — but must also fail on
   `chains_reconstructed_truncated > 0`, and it cannot see mid-chain
   aborts (P2's job) or version spans (P3's job): three confirmed
   members of the "well-formed but semantically wrong" class that only
   vendored capture-layer patches can expose.
4. Golden traces for `checks.py` tests must include the harness system
   prompt — D1's fix had to patch fixtures that were shaped like
   non-agent completions.
