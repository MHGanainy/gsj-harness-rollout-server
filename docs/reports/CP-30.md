```
config <path> invalid — 'harness.thinking': Value error, 'on' is not a pi
thinking level — use one of off|minimal|low|medium|high|xhigh|max; pi
silently clamps any other value to 'off' (CP-28), so this run would collect
a thinking-OFF control wearing the measurement's label; every non-off level
is wire-equivalent under qwen-chat-template, so 'medium' is the
conventional ON
```

One discovery the validator work surfaced: **pyyaml is YAML 1.1, so the
natural spellings `thinking: off` / `thinking: on` arrive as
BOOLEANS** — the default's own natural spelling would have died as
`Input should be a valid string`, naming no level. A `mode="before"`
leg maps `False` → `"off"` (honoring what the user wrote) and `True` →
`"on"` (which then gets the clamp rejection above, by its name).
Test-proven both ways.
