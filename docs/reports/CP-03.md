#### Findings (Step 5 observations that bear on assumptions)

1. **Chain-grouping degeneration, proven live** (row 8): with no engine
   token ids, `build_trace_from_completion` yields empty `prompt_ids`,
   `_find_extendable_chain` never extends (`0 < n` fails), and every
   completion becomes its own chain — 10 length-1 chains reported as
   `full=10, truncated=0`: a clean-LOOKING snapshot with zero actual
   merging. The specced G7 `chains_total == 1` requirement is what catches
   this; `truncated == 0` alone is blind to it.
2. **macOS Docker networking** (row 5): the task's `network: "host"` does
   NOT reach the macOS host loopback (host networking disabled in Docker
   Desktop — containers land in the VM netns; measured: host-net→127.0.0.1
   refused, host-net→LAN-IP ok, bridge→LAN-IP ok). Since `node.public_url`
   is used by BOTH the host-side rollout dispatch and the in-sandbox
   `OPENAI_BASE_URL`, the host LAN IP is the one URL that serves both.
   Echoes the predecessor's H200 networking archaeology (row 3).
3. **Persisted rollout results are NOT the callback payload** (row 16):
   `pipeline._storage_payload` strips `trajectory.status`/`trajectory.error`
   from `ses_*.json`. The receiver must validate the POSTed body.
4. **The persisted `transformed_request` is pre-engine-shaping** (row 11):
   `logprobs`/`top_logprobs`/`return_token_ids` are added at proxy time
   AFTER `save_message` — on-disk requests understate the wire request.
5. **The proxy logs nothing about capture** — uvicorn access lines only;
   the CompletionWriter files are the only record (A-5 context).
6. **Completions are counted per proxied request**: 10 per session
   (mini-swe-agent's default step limit), file-sequenced
   `0001-…`–`0010-…`; `record_count`/`raw_completions_total` agree.
7. **Upstream defects at the pin, pre-existing** (all reproduce with the
   patches reverse-applied): (a) `test_proxy.py` tests a `/workers`
   sglang-router discovery feature that does not exist in `proxy.py` —
   test-vs-src drift; (b) the sglang meta_info logprob-recovery test fails
   (`engine.py` stamping skips on length mismatch → `KeyError:
   'token_id'`); (c) a dashboard templates-route assertion fails. Recorded
   in REVENDOR.md so re-vendors don't chase them as regressions.
8. **mlx-lm's OpenAI dialect**: logprob entries are `{"id", "logprob"}`
   (not `token_id`), no `token_ids`/`prompt_token_ids`, default 512-token
   completion cap (`finish_reason: "length"` on every turn). A reminder
   that "OpenAI-compatible" is a family of dialects — pi's is the one that
   matters (A-12, CP-06).
9. **`gateway /health` reports `inference: {status: ok}` without the
   engine being exercised** — consistent with CP-02's H-41-adjacent
   observation on issue #39: a green topology does not prove a live LLM.
