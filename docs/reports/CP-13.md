#### Step 1 — `prompt_source`, and G1 landed (row 9 → PARITY)

**Where the value comes from.** `cli.py` is frozen, so the statement
arrives through `render_task_request`'s new keyword parameters:

```python
render_task_request(cfg, ..., prompt_source="free")                    # the CLI's path
render_task_request(cfg, ..., prompt_source="skill:summarize",
                    skill_card_text=<resolved card bytes>)             # the taskbank's path
```

This is not a workaround for the freeze — it is the honest shape. The
frozen CLI takes `--prompt`/`--prompt-file`, and **no resolution happens
there**: a prompt typed at the CLI *is* a free row, so `free` as the
default is the truth about that path rather than a placeholder for it.
Skill rows do not exist yet anywhere in this repo (ADR-0003); when the
taskbank lands it calls the same function with the resolved card, and
`skill_card_hash` is computed at render (convention 1, UTF-8 bytes
sha256) so nothing downstream has to trust a caller's arithmetic — and
the binding constraint is recorded in the spec: the pin is over the
card's raw FILE bytes, so a caller passes
`path.read_bytes().decode("utf-8")`, never `path.read_text()`, whose
locale encoding and newline translation would silently change the hash
for a CRLF card. Render validates every rejected shape with the
documented `ValueError`, non-string `prompt_source` included (it reached
`.startswith` and raised `AttributeError` until the CP's own adversarial
pass measured it): `taskbank`, `skill:`, `""`, `"skill: "`, `None`, `0`,
`True`, a list, a mapping, bytes. Card text on a `free` row raises.
A skill source WITHOUT card text is legal — see the limit below.
Metadata reserved keys are untouched (test-asserted).

The statement rides the CP-11-proven channel into
`trace.metadata.prompt_source`, and `check_skill_card` reads that hoisted
top level and nothing else. A `task_metadata` fallback was written first
and removed: the verification measured that every vendored shape carrying
`task_metadata` also carries `traces=[]` (`node.py:806-823`), so no
trace-level gate ever runs on one — admission catches them first — while
the leg widened the accept surface (a source stated at one level and a
hash at the other would have passed).

**Verbatim, the clean passes and the doctored failures** (run against the
two real recorded episodes):

```
# raw fixture-era bodies, verbatim — the honest fail-closed path
CP-07 sk-polar-c4eef751: validate_session_result -> ['G1:missing_evidence:prompt_source', 'G7:missing_evidence:settings']
CP-09 sk-polar-180dd057: validate_session_result -> ['G1:missing_evidence:prompt_source', 'G7:missing_evidence:settings']
# the same bodies carrying exactly what a CP-13 collection stamps

CP-09 stamped: validate_session_result -> []

G1 skill + unapproved card hash   -> ['G1:skill_card_hash_not_approved:0000…0000']

G1 unrecognized source            -> ['G1:missing_evidence:prompt_source']

```

**What "stamped" means, said plainly.** The two recorded episodes predate
`prompt_source` and the settings echo, so no clean pass on the verbatim
bodies is obtainable without inventing evidence. The test fixtures add
**exactly two statements** — `prompt_source: "free"` (true of both
episodes: each was submitted from the CLI with a typed prompt) and
`gsj_settings` read from `pins/settings.rendered.json` (the same document
the harness echoes, byte-compared in the suite against
`pi_harness.settings_json`) — and the raw fixtures on disk are untouched
(`git diff HEAD -- docs/polar/ docs/golden/` is empty). The verbatim
bodies' fail-closed findings are asserted as their own test, so the
posture is proven on a real artifact rather than assumed, exactly as
CP-11b proved it on the golden mapping.

**The limit, stated rather than buried.** G1 verifies a **stated** hash:
the submit path declares which card it resolved, and the gate checks that
declaration against the pins. That is self-reported evidence — the same
class as G7's stats block, which law 6 already declares the wire admits.
The predecessor's instrument was stronger in a specific way, and the CP's
verification made me name it rather than gesture at it: it read the card
*from the episode's own checkout* (`gsj-envloader task.py:878-885`) and
hashed those bytes, so a case repo whose card had drifted from the corpus
failed the gate. CP-13's gate catches a wrong or unpinned card; it cannot
catch a drifted checkout. That residual is now **wishlist item 9**, owned
by `pi_harness.py` — not folded into row 4, which owns a different
residual (tying the instruction text to the card needs ADR-0003's
`<task_id>` substitution semantics).

Shipping the card *text* instead of its hash was evaluated as the fix and
**rejected with measurement**: the 616-byte card does ride all three hops
(1,713 vs 435 bytes of trace metadata), but a submitter that can state a
hash can equally state text, so the receiver hashing handed-over bytes is
the same assurance one hop earlier. What recovers the predecessor's
instrument is hashing in the sandbox.

The API keeps that door open deliberately: `render_task_request` accepts
`skill:<name>` with no card text, states no hash, and G1 then fails closed
`G1:missing_evidence:skill_card_hash` until whoever reads the checkout
supplies it — so ADR-0003 is not forced into submit-side resolution. Row 9
claims PARITY on the gate's contract (approved-set membership for skill
rows, n/a for free rows, fail-closed otherwise) with the delta named
in-row.

#### Step 3 — the settings echo, hops executed (row 15's residual closed)

**Where it lands.** The harness writes the settings document into the
sandbox at `setup()`; the same in-memory object is merged into the
session's gateway-registry metadata:

```python
registry.register(self._session_id, metadata={"gsj_settings": settings_json}, status="")
```

Task metadata is the trainer's and fixed at submit time, so the harness's
own document cannot ride it — the echo joins the CP-11 channel one hop
later, at the registry the proxy stamps completions from. A-23 records
the assumption this rests on (harness and proxy share the gateway
process, which is what `import_path` means and what CP-06 verified live);
if it is ever false, `registry.get()` returns None and `setup()` raises —
the episode dies loudly at dispatch instead of running unechoed.

**Executed, not read** — all four hops against the real vendored classes
in the component venv:

```
$ PYTHONPATH=<repo> vendor/polar/.venv/bin/python hop_execution.py
hop1 dispatch-register: metadata={'case_id': 'case_0001', 'timestep': 12, 'prompt_source': 'free'} status=RUNNING
hop2 harness echo merged (real register(), session.py:87-88): metadata={…, 'gsj_settings': {'compaction': {'enabled': False}}} status=RUNNING (preserved)
hop3 _completion_metadata (server.py:371-377): {…, 'gsj_settings': {…}, 'session_id': 'sk-polar-hoptest', 'task_id': 't-hop'}
hop4 _chain_metadata (prefix_merging.py:371-375): trace top-level keys = ['case_id', 'gsj_settings', 'prompt_source', 'session_id', 'task_id', 'timestep']
gate: check_settings_echo(echoed)=[] check_skill_card(echoed)=[] | doctored compaction-on -> ['G7:settings_hash_not_approved:a1394185…']
ALL HOPS EXECUTED — the echo reaches trace metadata through real vendored code
```

Two properties the execution proves rather than assumes: the merge does
**not** clobber (`case_id`/`timestep`/`prompt_source` survive; `status`,
`registered`, `task_id` are unharmed — `status=""` takes the vendored
`status or info.status` branch), and Polar's own `setdefault` keys still
win at the stamp.

**What it echoes** — the rendered document as written to disk, not the
template. `check_settings_echo` canonical-hashes it (convention 2)
against `settings_hash`:

```
G7 echo doctored (compaction on)  -> ['G7:settings_hash_not_approved:a1394185bd6e8dcf…716d4e9f']
G7 echo absent                    -> ['G7:missing_evidence:settings']
G7 echo unhashable (NaN)          -> ['G7:settings_hash_not_approved:unhashable']
```

The single hash equality carries `compaction.enabled == false` with it:
the approved set holds exactly one value, so a document that hashes into
it *is* `{"compaction":{"enabled":false}}`. A separate field read would
be strictly weaker — it would admit a settings document carrying extra
unpinned keys. The same self-reported-evidence limit as the stats block
applies and is recorded: the harness states what it wrote.

#### Step 4 — the receiver's failure seam, over HTTP

The CP asked for two cured shapes. The CP's own adversarial pass measured
that a type-based catch cures only two of **seven** reachable pins faults,
so what landed classifies by **origin**: `checks.approved_set` raises one
`PinsConfigurationError` however the pins turn out unusable, and the
receiver maps exactly that type to 500. All seven, same envelope (a
pins-free member first, then a real body — the ordering that used to
half-persist):

```
missing pins FILE            HTTP 500 {"error": "pins configuration: pins file …/absent.json unusable: …"}
corrupt pins FILE            HTTP 500 {"error": "pins configuration: pins file …/corrupt.json unusable: …"}
pins path is a DIRECTORY     HTTP 500 {"error": "pins configuration: pins file …/pinsdir unusable: …"}
pins file wrong SHAPE        HTTP 500 {"error": "pins configuration: pins file …/wrong.json unusable: …"}
pins file UNREADABLE         HTTP 500 {"error": "pins configuration: pins file …/noperm.json unusable: …"}
missing pins KEY             HTTP 500 {"error": "pins configuration: pins key 'tool_roster_hash' missing, empty, or not a list in …"}
pins value a bare STRING     HTTP 500 {"error": "pins configuration: pins key 'tool_roster_hash' missing, empty, or not a list in …"}
control (pins healthy)       HTTP 200 {"accepted": 1, "rejected": 1}
```

Every failing row left `traces=[] quarantine=[]`; the control landed both
members. Of those seven, CP-11b had measured two; the pass added five,
and the last one was not a masquerade at all but a **fail-open**: a pins
value that is a bare string turns `hash in approved_set(...)` from set
membership into substring containment, so any prefix of the real hash
passed — live in every hash gate, G1 the newest of them.

**Atomicity, now against writes and not only validation.** `ingest`
validates *and serializes* every member, then stages every `.tmp`, then
commits by rename, unlinking every stage if any fails. The pass had
reproduced the old shape from wire content alone — a legal-JSON body
nested deeply enough to exhaust the stack inside the write loop wrote
member 1, orphaned a `.tmp` for member 2, and dropped the connection.
Regression-tested: an unserializable member answers 400 with both
directories empty; a staging failure answers 500 with nothing committed
and no orphan `.tmp`; and the session-id screen now caps at Polar's own
128-character `SESSION_ID_PATTERN`, so a legal-but-endless id is refused
at the shape screen instead of failing at the write.

**No exception leaves a connection unanswered.** A final catch-all
answers 500. That backstop earned its place immediately: a 4,000-mutation
fuzz of the real CP-09 body found a surviving never-raise breach — an
unhashable tool-call `function.name` reaching a frozenset lookup — which
is fixed at the source with a type guard and added to the
malformed-content corpus, but the backstop is what guarantees the
property rather than a promise that no such shape remains.

#### Verification

Seven adversarial lenses over the CP's own first cut (G1 fail-open and
false-rejection hunting; the settings echo, with an independent
re-derivation of the vendored hop chain; the receiver seam and its
atomicity claim; scope/freeze/DoD compliance; test integrity, including
mutating the implementation in a throwaway copy to prove the new tests
actually fail; documentation fidelity, every number and vendored citation
re-checked; and a predecessor-semantics lens reading `gsj-envloader`'s own
G1), each finding then handed to an independent refuter defaulting to
"refuted". Six of seven lenses returned DEFECT_FOUND. **Nine real defects,
all fixed before this commit** — the CP's first cut was wrong in ways the
DoD as written would not have caught, which is the point of running the
pass at all.

**Blocking, fixed.** The report claimed the suite byte-compared the
stamped `gsj_settings` against `pi_harness.settings_json`. It did not —
the literal was hard-coded in three places, and the lens proved the
decoupling by editing the harness constant *and* its unit test in lockstep
in a scratch copy: 93 passed, while every real episode would have failed
G7. The chain is now asserted end to end (harness document == the pinned
`pins/settings.rendered.json` == a document whose canonical hash is in
`settings_hash`).

**Fail-open, fixed.** `approved_set` type-checked nothing, so a pins value
that is a bare string turned `hash in approved_set(...)` into substring
containment: a one-character stated hash passed G1, and the same hole was
live in G2/G3/G7. Pre-existing, but CP-13 is what put a wire-supplied hash
on top of it.

**Receiver, fixed (five shapes and one dropped guarantee).** A corrupt
pins file answered 400 — the masquerade the CP was chartered to cure,
reappearing because `JSONDecodeError` subclasses `ValueError`; unreadable,
directory, and wrong-shaped pins files dropped the connection. Now
classified by origin. And batch atomicity was validation-only: the lens
reproduced a half-persisted batch plus an orphan `.tmp` plus a dropped
connection from wire content alone. Now two-phase with cleanup, plus a
catch-all so nothing goes unanswered, plus the session-id cap.

**Never-raise, fixed.** A 4,000-mutation fuzz found an unhashable
tool-call `function.name` raising `TypeError` out of `validate_session_
result` (pre-existing; the CP-11b corpus covered the unhashable `id` and
`tool_call_id` but not the name). Type-guarded, corpus row added — the
same class of fix, in the same file, that CP-11b's own pass forced.

**G1, fixed in three ways.** (1) `render_task_request` rejected a
non-string `prompt_source` with `AttributeError`, not the documented
`ValueError`, and accepted blank skill names — the untested half of a
tested contract. (2) `_stated`'s `task_metadata` fallback was dead for its
stated purpose (every vendored shape carrying `task_metadata` also carries
`traces=[]`, so admission fires first) while widening the accept surface;
removed, and the false claim struck from the spec and this report.
(3) Row 9 claimed PARITY with a capability column describing the
predecessor's instrument and a mechanism column describing a weaker one,
and its stated residual was then filed under row 4, which owns a
*different* residual. The delta is now named in-row and owned by a new
wishlist item 9. The API was also relaxed so a skill row may omit
submit-side card text, which stops the register from prescribing
submit-side resolution to a taskbank that has not chosen yet.

**Evaluated and rejected, with measurement.** Shipping the card *text*
instead of its hash — my own first instinct, and the obvious reading of
the spec's evidence column — buys nothing: the lens measured that the
616-byte card rides all three hops fine (1,713 vs 435 bytes of trace
metadata), but a submitter that can state a hash can equally state text,
so the receiver hashing handed-over bytes is the same assurance one hop
earlier. Recorded so the dismissal carries its measurement.

**Recorded, not fixed.** G1's `not_approved` detail embeds wire content
where other gates embed a computed digest; exercised over HTTP with
newlines, 1 MB, lone surrogates and NULs (no crash, no forged finding, no
log injection — `json.dump` and the logger's list repr escape all of it),
so it is bounded to 64 characters as hygiene rather than treated as a
defect. The CRLF hazard on the card-hash convention (pins hash file bytes,
render hashes decoded text) is dormant — both staging cards are LF, and
the constraint is now binding in the spec — and arms only when the
taskbank starts resolving cards, whose owner is ADR-0003.

**What held under attack**: the settings echo's four hops re-derived
independently against the real vendored classes, including the ordering
proof that `setup()` precedes every completion so the chain's first
completion metadata carries the echo; the merge preserving status,
