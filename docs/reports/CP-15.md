**What the hand-rolled index had been hiding.** (a) The G3 roster had no in-suite assertion at all — and building one surfaced that the wire form alone cannot see default/int-type drift (the layered pin above). (b) A hazard class the numpy backend could not have: Chroma's default embedding function — attached silently by `get_collection`'s *default parameter* — is a different MiniLM (ONNX) at the same 384 dims, so an accidental text-op would have mixed two implementations without an error; guarded structurally (a raising EF on every handle) and by a bit-exactness test (stored vector == pinned encoder output). (c) `embedding.normalize: false` was latent config space whose defined semantics (raw dot-product ranking) only the old backend could honor — now retired loudly, the `search.method: exact` pattern. (d) The old filesystem store accepted any case id; Chroma's collection-name rules narrow the space (contract-valid `c1`/`case_`/`x-` now impossible) — accepted and made loud at config load, ADR-0016 corrected. (e) The numpy backend was restart-equivalent by construction (files re-read every init); Chroma's per-path process cache broke that silently — `rm -rf` of the store left a running service serving the unlinked inode and `/admin/reindex` "reusing" a phantom. Fixed: reindex evicts the cached system (scoped to its path) and is regression-tested. (f) The cross-process identity test became self-comparing under Chroma's client cache (same path → same in-memory system) — now loads from a copied store, a genuine disk round-trip.
