#### Step 1 — the leak, its cure, and what the cure itself taught us

The reproduction and cure, verbatim, in a scratch clone of a
recipe-exact `case_0001` (real staging pages, `main` = full-document
commit, `timestep-12` = one truncation commit — the estate is down on
this host, so this is the CP's sanctioned fallback and is labeled as
such):

```
### BEFORE — the flags at pi_harness.py:127 until this CP
$ git clone --branch timestep-12 --single-branch file://…/case_0001 work_before
$ ls md | tail -1                          → page_0012.md      (worktree clamped)
$ git show HEAD~1:md/page_0018.md | head -3
## Page 18
An undated note, later attributed to Marta Hofstetter, places the …    (LEAKED)
$ git log --oneline
e1518ec timestep-12: truncate after page 12
77e5b36 case_0001: full document (18 pages)                    (total leaked too)

### AFTER — the fixed step
$ git clone --depth 1 --branch timestep-12 --single-branch file://…/case_0001 work_after \
    && git -C work_after remote remove origin && rm -rf work_after/.git/logs
$ git show HEAD~1:md/page_0018.md          → fatal: invalid object name 'HEAD~1'.
$ git log --oneline                        → e1518ec timestep-12: truncate after page 12
$ git remote                               → (no output — no remotes)
$ git fetch origin                         → fatal: 'origin' does not appear to be a git repository
$ git rev-parse --is-shallow-repository    → true
$ git cat-file -e 77e5b36…                 → exit 1   (main's commit ABSENT from the object store)
$ git cat-file -e 2a2c39a…                 → exit 1   (the page_0018 blob ABSENT)
$ grep -rn "file://\|http://" .git/ | wc -l → 0       (no URL recoverable)
```

Closed at the **object level**, not the ref level. The shallow clone
broke nothing: `diff -r work_before work_after --exclude=.git` reports
the worktrees identical, and `read` (head), `grep`, `find` (12 pages),
`ls`, and `rg` — the CP-07 trap's own tool — all behave unchanged.

**The finding the verification forced**: the CP's two named mutations
were not enough. After `git remote remove origin`, the reflog
(`.git/logs/HEAD`) still said `clone: from <url>` — a bash agent reads
it back and `git fetch <url>` works again. Hence the third mutation in
the same step, the logs scrub, after which no URL exists under `.git/`.
**The residual, stated rather than hidden**: an agent that *guesses* the
Forgejo endpoint can still re-clone over the network, because the estate
as built allows anonymous git read (CP-04 measured 4 refs/repo). That is
estate posture — shared with the predecessor's estate, unfixable from
`gsj_rollout/` — and its cure (credentialed clone URLs or sandbox egress
policy) is now named in row 2 for the estate bring-up. §5's claim is
restored scoped to what this repo controls: **offline, nothing past page
T is reachable from the checkout**. The rendered command is
regression-locked by `tests/test_pi_harness.py` (exact-string assert on
what `setup()` actually execs, polar stubbed).
