## Notes

### Step 1 — the pins decision, and its failure mode

**Decision: compose three candidates; the fourth is the real answer and
is deferred, making this cure interim.**

1. **The example ships its own byte-identical copy** of the thinking-on
   pins (`example_project/pins/thinking-on/pins.gsj.json`, sha256
   `832255e4…`, copied from library `2923cc0`; provenance and the drift
   story in `example_project/pins/README.md`) — because a
   `pip install`-only consumer has NO thinking-on pins anywhere on disk
   (the wheel packages only the off reference, ADR-0019/0024 posture),
   so no amount of derivation or documentation could point at a file
   that does not exist.
2. **`train.py` derives and sets `GSJ_PINS_PATH` before anything
   imports `checks`.** The mechanism the CP-11b fact forced: the
   resolution happens at `gsj_rollout.checks` **import**
   (`checks.py:118`), so train.py's heavy imports moved behind a
   preflight (`_heavy_imports()`, the module docstring says why —
   external F-41). The preflight reads the effective mode
   (`--thinking` > config, mirroring the validator's YAML-1.1 bool
   mapping), sets the variable to the shipped copy when unset and the
   mode is on, and **classifies** an inherited variable by its G6 tail:
   mode/pins disagreement in either direction is a refusal with words,
   before any submit. Bonus of the same ordering: `--help` now works
   with no closure installed, and the packaged-pins warning (F-39) no
   longer prints on the default path (the variable is set).
3. **The run book makes the receiver leg a loud step**: the serve
   command itself carries `GSJ_PINS_PATH` inline (it cannot be skipped
   by skimming), §Thinking states what each leg needs, and the
   "wrong pins" symptoms are written per leg so they are recognized,
   not debugged.
4. **The right answer is the library's** — wishlist 28: package
   `pins/thinking-on/` beside the existing packaged copy (data-only,
   the ADR-0017/0019 force-include as-is, no `checks.py` line) with a
   documented packaged path. ADR-0024's posture (default resolution
   means off; explicit env means everything else) survives unchanged.
   Until then the example's copy can drift when the library re-pins —
   so train.py's preflight also compares the copy's six non-G6 sets
   against the installed wheel's reference pins and warns in words
   (best-effort, never fatal).

**What a stranger sees if the wrong pins resolve**, the deliverable
sentence by leg:

- *train.py's own leg* — they see this, and no estate is spent
  (measured deskside, exit 1):

```
train.py: thinking is 'medium' (ON) but GSJ_PINS_PATH=<path> carries the
thinking-OFF G6 tail — every collected episode would be quarantined
G6-only (G6:prompt_suffix_ne_tail_ids on each) and the estate's time
spent for nothing. The mode and the pins are two statements of one fact
(library ADR-0024). Cure: unset GSJ_PINS_PATH (train.py then selects
./pins/thinking-on/pins.gsj.json itself) — and start `gsj-rollout serve`
with the thinking-on pins too, both law-6 legs. For the off control
instead: --thinking off
```

  (and the symmetric off-mode-vs-on-pins message, also measured, which
  additionally says a serve restart is required because pins resolve
  once per process). If a wipeout reaches collect anyway (a foreign
  file the classifier passed through), an all-G6 zero-yield prints its
  own interpretation naming the receiver leg and §Thinking.

- *the receiver's leg* — the miss train.py cannot see (client polls
  Polar, never the receiver's disk — law 6 keeps the verdicts
  independent): collect looks healthy while `traces_dir` stays empty
  and `<traces_dir>/quarantine` fills G6-only. §Thinking states this
  shape as a check-once-after-first-collect step. **This is the leg
  CP-32 must exercise for real.**

**Complete or interim? Interim**, stated everywhere it appears
(pins/README.md, FINDINGS F-40, wishlist 28): the copy is the
mechanism by which a pip-only consumer can run the shipped default at
all, and it dies the day the wheel carries both files.

### Step 3 — the flag, and what a run prints

`--thinking LEVEL` (default None → the config's value; `--help` names
the levels, the shipped default, the ~2.7×/~2× cost, and the
restart-serve-on-flip rule). A bad level goes through the library's own
validator via re-validation (assignment would bypass it), so the
stranger gets the CP-30 message with the clamp explanation — measured
deskside. Every run's first lines, so a log always names its regime:

```
[train] thinking: medium (config.yaml)          ← or (--thinking)
[train] pins: GSJ_PINS_PATH=…/pins/thinking-on/pins.gsj.json (set by
        train.py for this process — the RECEIVER is a separate process
        and needs the same variable; RUNBOOK §Run)
[train] thinking-on costs ~2.7x wall clock and ~2x tokens vs off
        (CP-28, 2026-08-14; median episode 7.7s -> 21.1s) — a slow
        collect is the mode working, not a malfunction; --thinking off
        collects the control
```

The RLVR fact is met **where the reward is attached** (grade_and_ingest,
right after the `reward distribution:` aggregate), and it is *this
collection's own measured number*, not a quoted one — computed
tokenizer-free from ids 151667/151668 over the mask-1 spans of the
ingested records (the CP-28 §4 derivation, ~15 lines,
`_think_token_share`):

```
[train] thinking-on collection: NN% of trainable (mask-1) tokens are
        <think> tokens (…/…; CP-28 median: 67%) — under RLVR/GRPO that
        share of the gradient mass rides reasoning. OPD: that is the
        point. SFT on own reasoning at 0.6B: don't — derive a think
        submask from ids 151667/151668 or use a teacher (CP-28 §4)
```

It prints only when think tokens exist in the data — the mode of a
collection is read from the collection, never assumed from config, so
grading an off directory stays byte-identical to CP-27's output and the
line's absence is itself the off signature.
