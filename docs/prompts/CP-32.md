# CP-32 — M9d: the stranger test, both modes

You are executing CP-32 of `gsj-harness-rollout-server`. CP-26 tested
whether a stranger could get from zero to a step. This tests whether they
can run the shipped triple — config, bank, `train.py` — in **both modes**,
from the run book alone.

**The deliverable is the friction list, not a green run.** CP-26's F-14
through F-39 came from exactly this exercise and were its most valuable
product. A run that works while a stranger flounders is a failure.

**Needs GPU and estate.**

## The posture — read this twice
You are the stranger. Adopt it literally:

- **`RUNBOOK.md` and the example project are your only inputs.** Not the
  charter, not the reports, not `staging/`, not the library's `docs/`
  beyond what the run book links.
- **A fresh environment**: new directory, new venv, nothing reused. The
  library now installs from PyPI (CP-29) and both repos are public — so
  unlike CP-26, **acquire them the way a stranger would**: clone from the
  public URLs, `pip install gsj-harness-rollout-server`. If that path
  fails, that is the finding, not a reason to side-load.
- **Estate services are inherited** (Forgejo, MCP, the engine) — a
  stranger would be handed those.
- **Write down the friction before fixing it.** Every use of out-of-band
  knowledge is a finding: what you knew, where it should have been
  written, what a real stranger would have done.
- **Do not improve the docs while running.** Log, finish, then fix.

The sequence a stranger would follow: clone, install, configure, serve as
