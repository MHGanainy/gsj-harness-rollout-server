# CP-34 — M11a: the estate bootstrap

You are executing CP-34 of `gsj-harness-rollout-server`. A **new repo**:
the demo a stranger uses to go from their own corpus to a running estate.

**The audience is not the trainer.** `-examples` shows someone how to
train. This shows someone who has documents, a config, and an inference
endpoint how to get their first trajectory. Different entry point,
different success criterion.

**Success criterion for this CP**: from an empty directory on a clean
box, a stranger who has `pip install`ed the library and written a
`config.yaml` runs **one bootstrap command** and ends with a running
estate whose corpus is ingested and verified. Nothing side-loaded, no
repo cloned by hand.

**CP-35 does the trajectory views and the run-through. This CP stops at
"the estate is up and the corpus is in it."**

## Step 1 — ADR: how Polar runs
The decision that defines what "bootstrap" means. Forgejo and MCP are
containers with compose files. Polar's rollout server and gateway run
from `vendor/polar/.venv` — a *checkout*, which is precisely what
CP-32's F-45 measured a stranger tripping over.

Three options:
- **A container** — build an image carrying Polar's venv and our wheel,
  compose it beside the others. The stranger never sees a venv.
  **Recommended**, because it is the only option where "one command"
  is true.
- **Clone at bootstrap** — the script fetches the library repo for
  `vendor/`. Cheaper, but reintroduces the two-repo dance publishing was
  meant to end.
- **Documented manual step** — honest, and leaves the hard part exactly
  where CP-32 found it.

Decide on what you measure, not on my recommendation. If the container
is more than this CP can carry, say so and take the clone with the
container named as the durable answer.

Whatever you choose, record: how the wheel gets in (PyPI, pinned
version), how `import_path` resolves `gsj_rollout.pi_harness` in that
process, and how `GSJ_PINS_PATH` reaches both law-6 legs.

## Step 2 — The stranger's inputs, and only those
Exactly three, and the repo's README must be able to state them in a
sentence:

- **a corpus** in the contract's shape
- **a `config.yaml`** — and this is a design job, not a copy. CP-25
  classified the library config's keys into endpoint / tuning / estate
  fact / lore. In *this* repo most of the estate is stood up by the
  bootstrap, so most estate facts are derivable. **What is genuinely
  the stranger's?** Their corpus path, their inference emodel name. Aim for that and justify anything else.
- **an inference endpoint** — a URL and a model name they already have.
  Do not pin a model; do not stand up a serving engine. State what the
  endpoint must satisfy (the CP-04′ engine legs: a tool-call parser,
  a context window ≥ the config's, and — the silent one — sampling
  defaults, since pi sends none).

## Step 3 — `validate` a pip-install consumer can reach
The contract says verify before ingesting, and `ingest_corpus.py
validate` is exactly that — but it lives in the library's `corpus/`,
which a wheel does not carry. **A stranger who must clone a repo to
check their corpus does not have a pip-install path.**

Decide: the bootstrap image carries the pipeline, the demo repo vendors
it, or the library ships it (a library change — minimal, and say what).
Whichever: **the stranger must be able to validate their corpus before
the estate is stood up**, and get the PASS table with its per-case rows.

## Step 4 — The bootstrap
One commavalidate the corpus (Step 3) and **stop loudly** if it fails — nothing
  else should run against an invalid tree
- stand up Forgejo, the MCP service, the network
- scaffold the corpus into Forgejo, ingest it, build the taskbank
- run `verify` and show its table
- stand up Polar per Step 1
- print what is running, on what ports, and how to stop it

**Every failure must say what to do.** CP-27's validator messages are the
standard, and CP-26's F-22 is the shape to avoid — the MCP secret had no
acquisition path and surfaced mid-episode. Generate it, state where it
lives, and check it before an episode is spent.

Idempotence matters: running it twice on an existing estate should be
safe and say so, not half-rebuild.

## Step 5 — The synthetic corpus
