## Step 1 — The logprob discipline
Implement in `checks.py`, wired through the `run_trace_checks` seam
CP-08 proved live. The rules, with CP-09's measurements as the authority:

- **Sentinel rejection**: any `mask==1` position with logprob ≤ −9000.0
  fails hard. This is the vLLM absent-logprob sentinel; it is finite and
  ≤ 0, so the naive discipline admits it. CP-02 established upstream has
  **no** value-level logprob validation anywhere — this guard is
  load-bearing, not duplicative.
- **Absent logprobs**: `response_logprobs` null or shorter than
  `response_ids` on a trainable trace fails hard. Upstream's own
  rejection is status-derived, not a config surface — do not inherit that.
- **Placeholder discipline**: `0.0` at `mask==0` is Polar's alignment
  placeholder and is expected. `0.0` at `mask==1` is the suspicious-zero
  rule — and CP-09 measured it on **both** stacks (golden 20/292,
  collected 15/363) as bf16 rounding of genuinely-near-zero RAW logprobs.
  **Platform-condition it**: a configurable threshold/allowance rather
  than a hard fail, defaulting to whatever CP-09's measurements justify,
  with the reasoning in the docstring. A rule that fires on every
  well-formed MLX trace is a rule nobody will keep.
- **Raw semantics**: captured values are RAW model logprobs (CP-09
  measured renormalization fitting ~6× worse). No renormalization
  transform in the discipline math.
- **No replay-style rule may teacher-force a merged stream** on
  multi-turn traces without de-stitching first (F2). If you implement any
  replay check at all, it de-stitches via the config-pinned glue ids —
  and note the F2 caveat: the de-stitch identity is *session-specific,
  not structural*, so such a check can be wrong on a session where
  turn-1's body doesn't retokenize identically. **Recommendation: do not
  implement replay in `checks.py` this CP** — it needs an engine, it is
  unexecutable on Mac estates (F3), and its tolerance anchor doesn't
  transfer (F4). Record why rather than building it.

## Step 2 — G5, the cutoff
The requirement, not a nicety. Reconstruct the page census from the
trace's tool-result texts and fail any trace citing a page > the
episode's timestep.

- Use the spec's two regexes (`"page"\s*:\s*(\d+)` and
  `md/page_(\d{4})\.md`) — they are the compatibility contract with the
  MCP service's result shape, and CP-08's smoke already exercised them
  on a real Polar trace.
- Filter to `mcp_gsj_search_case` results only — decisions tools are
  cutoff-exempt (ADR-0007 of the predecessor).
- The timestep comes from the trace's own metadata (the harness settings
  ride through) — **not** from a caller-supplied argument, or the check
  can be told what to believe.
- Note in the docstring that this is the *backstop*: the MCP service
  enforces the cutoff server-side from verified token claims; this
  catches a service that misbehaved or a result shape that changed.

## Step 4 — The template findings (housekeeping)
From the investigation. Documentation only — no template change, no
re-pin, no code beyond what Step 1–3 already writes.

- **ADR-0007 amendment** (append a dated section, do not rewrite):
  record the three alternatives — keep the stitch, symmetric served
  template, patch Polar's grouping — with the prior art now known (TRL
  ships `qwen3_training.jinja` with exactly Direction A plus
  `is_chat_template_prefix_preserving`; verl carries a stitch-analogue;
  NeMo-RL and OpenRLHF have the same defect open). State why the stitch
  won *at this point in time* — the flip re-derives pins and breaks
  golden comparability, both of which CP-04′ does anyway — and that
  Direction B is refuted with a citation (the empty pair is the
  reasoning-suppression signal; a vLLM maintainer observed the model
  stops emitting `</think>` without it). State the trigger that would
  force it earlier: a session where turn-1's body does not retokenize
  identically breaks de-stitching while the merge still succeeds.
- **Finding (a) — the G4 blind spot.** G4 pins the *codec* snapshot's
  template (`a55ee1b1…`); the engine renders with the *served* snapshot's
  (`87a2728c…`). Byte-identical renders on pi's normalized shapes today,
  so harmless — but the gate as specced would pass without ever having
  measured the serving-side artifact. Gap-register row + a spec note that
  G4's input must be the template the engine actually renders with. Note
  that the CP-04′ template flip fixes this incidentally by making the
  served template an explicit pinned file.
- **Finding (b) — the silent one.** The codec template coerces
  non-string `content` to `''`, so an offline re-render of pi's
  typed-parts messages silently produces empty user turns. Live is safe
  (vLLM flattens before templating). Spec rule: **any check that
  re-renders prompts from message logs must normalize content parts
  first**, or it validates against a prompt that never existed. This is
  the one genuinely silent hazard the investigation found.
- **Finding (c) — thinking-on is a worse regime.** History strips
  variable-length reasoning per turn; a fixed-ids stitch structurally
  cannot repair that (strict-extension fails → split chains → the
  receiver rejects, loudly). Assumption row so nobody flips the flag
  expecting coverage; the fix there is TRL's general template.
- **CP-04′'s Definition of Done gains** (write it into the charter's plan
  section so it is inherited, not remembered): render both template
  variants against the same history; confirm the symmetric variant makes
  turn-2 a strict prefix-extension; adopt it via `--chat-template`;
  record the file in the serve argv; re-derive G4; retire
  `generation_prompt_glue_ids` while leaving the stitch code dormant as
  fallback.
