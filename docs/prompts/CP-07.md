## Step 1 — ADR-0006: the harness contract
Decide and record before writing:
- **What the harness receives.** Polar's `AgentSpec.settings` is the
  channel. Enumerate the keys: `case_id`, `timestep`, the Forgejo clone
  URL pattern, the MCP base URL, the token secret's env-var name, the TTL,
  the tools allowlist, pi's in-image paths. **Row 31's obligation: the
  tool roster is a config value, not an argv literal** — the spike baked
  it in and that is the named anti-pattern; G3 needs a pinned input.
- **Where the token is minted.** `run_steps()`, not `setup()` — the proxy
  env is only available there (CP-06's trap), and the token must be fresh
  per episode. State the claim set `{case_id, timestep, episode_id, exp}`,
  the algorithm (HS256), and that the secret never appears in argv, logs,
  or metadata.
- **Where the cutoff is enforced.** Server-side, from *verified claims
  only* — the harness supplies the token, the MCP service decides. State
  that the agent can read the token and why that is acceptable (every call
  it can make is already scoped to its own timestep; mutation breaks the
  signature).
- **What `setup()` does vs `run_steps()`.** Clone at
  `timestep-{T}` in `setup()`; render `.pi/mcp.json` and pi's model config
  in `run_steps()`. Loud exec checking in `setup()` — CP-06's trap
  produced "exit 127, zero records" with no diagnosis.
- **What `postprocess()` recovers.** pi's transcript, and the deliverable
  from `out/` if one exists. The session dir is destroyed after; this is
  the only exit. Decide where they land and how the trace references them.
- **`runtime.workdir` is never set to a harness-created path.** State it
  as a rule with CP-06's evidence.
