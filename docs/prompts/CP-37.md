# CP-37 — M12a: the model-dependent surface

You are executing CP-37 of `gsj-harness-rollout-server`. Every measured
number in this project since CP-04′ came from Qwen3-0.6B. CP-36's P2 was
**not hit** — the endpoint brought was the reference stack — so what a
different model breaks is still unmeasured.

This CP makes the model-dependence **explicit and derivable**. CP-38 runs
a second family end to end and finds out what was wrong.

**Freeze-lift: the demo repo (unrestricted), `pins/derive_pins.py`
**only if the derivation genuinely belongs there** — decide and say —
and `docs/**` here. NOT lifted: anything under `gsj_rollout/` (budget
1,999/2,000; a library change needs a §1 raise first), `vendor/`,
`corpus/`, `mcp-service/`, `forgejo/`, `spike/`, `staging/`, `tests/`,
`.github/`.**

**Needs an endpoint.** The reference stack is the control. A second
model's *tokenizer* — local snapshot or a second served model — is
enough for Step 6; a second engine is CP-38's.

Read first: `docs/reports/CP-36.md` §Step 4 and §the findings (what
preflight probes today, what it cannot see, and its now-proven shape —
you are extending working code, not designing from scratch);
`docs/reports/CP-04prime.md` §Step 2 (the template proof: render both
variants against the same captured history, check strict
prefix-extension — CP-04′ measured Qwen3's divergence at index 2018 of
2022 on exactly four tokens); `docs/decisions/ADR-0024` (G6's per-mode
pins and what its tail *means*); `docs/checks-spec.md` §G6;
`pins/derive_pins.py`.

## Step 1 — Enumerate what the model actually decides
Desk work, and the CP's spine. Walk every artifact and say, per item:
**does it change with the model, how is it derived, and who derives it
today?**

At minimum — and what you find beyond this list is the interesting part:

- `end_of_turn_toail_ids`
- G4's tokenizer and chat-template hashes
- G2's system-prompt hash — does the render depend on the model? measure
- **the chat template's prefix-extension property** — the behaviour that
  decides whether Polar's grouping merges natively or the stitch is
  needed. Not a hash.
- **G6's meaning.** Its subject is the empty think block, a Qwen
  hybrid-reasoning artifact. On a model without that mode, what does G6
  assert — the bare generation prompt, something else, or nothing?
  **Say plainly if G6 is Qwen-family-specific.** That is a legitimate
  finding, not a failure.
- **the thinking surface.** `thinking: off|minimal|…|max` is pi's
  passthrough to a Qwen feature. On a model with no such mode, what does
  a non-off value do? (CP-28 measured pi clamping *unknown values*; a
  model with no mode is a different question.)
- sampling defaults (unprobeable — wishlist 38) and the context window

Classify each: **derivable from the endpoint**, **derivable from a local
snapshot**, **estate-sidor **a human decision**. That
classification is the deliverable.

## Step 2 — The template probe
The behavioural question nothing currently checks, and the one most
likely to break silently.

Render a two-turn history under the served model's template and test
whether turn 2's `prompt_ids` is a **strict prefix-extension** of turn
1's. Make CP-04′'s hand-measurement a probe.

Then decide what the demo tells a stranger when it fails. Options: a
symmetric template variant (TRL ships one for Qwen3; other families may
need their own), the glue stitch if the divergence is constant, or a
plain statement that this model needs work first. **Whichever — they
must learn it before an episode is spent**, because the failure
otherwise appears as `chains_total: N`, which nothing surfaces to them.

Say what the probe needs. If `/tokenize` suffices, good; if it needs a
local snapshot and a template, say what that costs.

## Step 3 — Derive, don't just detect
CP-36 confirmed the preflight's tokenizer rows FAIL loudlye the
G6 quarantine consequence — but the cure is still wishlist 35's manual
pins walk. Close that.

On mismatch, **derive the correct values from the endpoint** and produce
a pins document for this model: the EOT id, the tail ids, whatever else
Step 1 classified as endpoint-derivable. Then write it where
`GSJ_PINS_PATH` will find it, or print exactly what to do with it.

**Values that cannot be derived must be named, not defaulted.** A pins
file with a plausible wrong value is worse than a missing one —
CP-19's packaged-pins reasoning, and it bites harder here because these
feed gates.

Decide where this lives: the demo's preflight, `derive_pins.py`, or
both. If `derive_pins.py` is the right home, that is a `pins/` lift and
the library's tooling improves for it.

## Step 6 — Prove the derivation against the reference, then reach further
**The control**: run the derivation against the reference stack and
confirm it reproduces the pinned values exactly — EOT id, tail ids, and
whatever else Step 3 covers. A derivation that gets the known answer
right is the precondition for trusting an unkne.

Then, if reachable: point it at a **second model's tokenizer** without
standing up a second engine — a local snapshot, or a second served
model. Report what it derives and whether it looks sane. Not an episode;
just the values. If the template probe can run against that snapshot
too, run it — that is the most valuable single number this CP can
produce, because it is the first evidence about a non-Qwen template's
prefix behaviour.
