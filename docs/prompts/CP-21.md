## Step 1 — Answer the seven inputs at a desk
CP-20 named them so this is cheap. Write each answer before any cluster
time:

1. **The trainer-generation fork (F-11)** — classic-batch feed via the
   bridge, v1 TQ residency, or a custom `AgentLoop` that calls
   `gsj-rollout submit`. **Recommendation: classic batch**, matching
   CP-17's shape — it is the seam CP-20 built for, and the other two
   change who drives generation, which is a different experiment.
2. **Environment and co-residency** — verl brings FSDP/Megatron + Ray.
   CP-17's separation (serve GPU 3, train GPU 5) is the template.
3. **Weight sync** — NCCL resharding is unavailable when the engine isn't
   verl's, so expect checkpoint reload again. Same A-13 drain rule.
4. **Reward** — reuse CP-17's `reward_cited_pages.py`. Widvantages are identically zero (F-02).
5. **uid grouping (F-10)** — **this one is not optional.** With the
   default uid every group is a singleton, and a singleton's advantage is
   its raw uncentred reward: the loop would train on raw rewards while
   looking like GRPO. Decide how episodes group — n per prompt, or a
   grouping key — and state the collection cost.
6. **Config verl needs that slime never asked for** —
   `algorithm.adv_estimator` (default GAE needs a critic; GRPO or RLOO
   must be chosen), `rollout.calculate_log_probs`, `loss_agg_mode`,
   `algorithm.rollout_correction`.
7. **Replay-style validation** — the measured floor (0.008 / 0.21), never
   the CP-18 anchor.

## Step 3 — Collect, convert, train
One iteration. N small, but **N must satisfy the grouping decision** —
if GRPO needs n per prompt, the collection is n× larger than CP-17's, and
CP-09′ measured ~19 submissions per qualifying episode. State the budget
before collecting, then report what it actually cost.

Assert per episode before conversion: `COMPLETED`, no builder findings,
`chains_total == 1`, cutoff held. The H-41 stance is yours — CP-17 relaxed
it loudly and said why; do the same, either way.

Then: convert through the bridge with the three assertions live, feed
verl, take one optimizer step. Record loss, whether gradients were
non-zero, the reward distribution, **and the advantage distribution** —
F-10 makes that last one load-bearing rather than decorative.

## Step 4 — Sync and prove it took
CP-17's mstandard and it is a good one: **measure the
instrument's noise floor first** (two probes on identical weights — CP-17
got exactly `0.000000`), then measure across the sync. With a zero-noise
instrument the delta can only be the weights.

Corroborate at least once more — the engine reporting the new checkpoint,
or a weight-tensor diff. An unproven sync is two batches, not a loop.

## Step 5 — Collect again
One more collection through the same path, against the updated policy.
Compare what is comparable: gates still pass, cutoff still holds, traces
still convert. **Do not make a learning claim** — CP-17's discipline here
was exemplary and the same constraints apply, more so with a batch shaped
by grouping.
