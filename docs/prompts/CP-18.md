## Step 2 — The workflow
One file, `.github/workflows/ci.yml`. Triggers: push and pull_request on
`main`. Python **3.12 only** — every environment this project runs is
3.12 (mcp-service, Polar's venv, the H200 collector), so a matrix would
test a configuration nobody uses. If the root suite fails on 3.12 for a
reason that isn't a real bug, tinding.

Jobs, in rough order of what breaks first:

1. **root** — `pip install -e ".[dev]"`, `pytest -q`. Expect 129.
2. **corpus** — its own `pytest.ini`; run per CP-14's recipe. Expect 44.
3. **mcp-service** — its own venv and requirements (chromadb, the MiniLM
   model). **This is the one that may not work as-is**: it downloads a
   model at first use and builds bares through the pipeline. If it needs
   network, caching, or too long a runtime, say so and decide — cache the
   model, mark it a slower separate job, or exclude it with the reason
   recorded. Do not silently skip it.
4. **wheel + install proof** — build, then in a fresh venv *outside the
   checkout*, `pip install` the wheel, import `checks`, and validate the
   real CP-09′ callback body. This is the leg CP-16 fixed and the one most
   likely to regress silently.

Keep the file readable. No matrix, no reusable workflows, no caching
beyond what job 3 genuinely needs.
