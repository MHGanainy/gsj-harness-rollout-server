## Step 1 — ADR-0016: what changes and what may not
Decide and record before writing.

**The four invariants that must survive byte-identical.** State each with
what breaks if it moves:
1. **Tool names, signatures, and docstrings** — G3 hashes the wire roster
   (`a7a7956b…`); any drift fails every episode until a deliberate
   re-pin. Assert this in the service's own tests, not just here.
2. **Result shape** — every `search_case` hit carries `page` (int) and
   `file` (`md/page_NNNN.md`) in the form G5's two regexes parse. This is
   the comtract any backend must keep.
3. **Cutoff filtering before ranking** — the candidate set is constrained
   to `page <= T` *before* similarity ranking. Chroma's `where` clause is
   the right primitive; **verify empirically that it pre-filters rather
   than post-filters**, because a post-filter returns fewer than `k` and
   moves the recall boundary. Design the test before the code: query at a
   tight timestep, confirm `k` results drawn from the in-cutoff set.
4. **T from verified token claims only**, never a request field.

**What is accepted as changed.** Approximate retrieval — this is a RAG
system and HNSW is what Chroma gives. So byte-reproducible retrieval stops
being a guarantee. **Measure it** (Step 4) and record the result as an
assumption row rather than asserting either way.

**What Chroma is for.** State the reason plainly: a query API and
persistence you do not maintain, and a path to a corpus where brute-force
stops being free. If the honest answer is "it buys little at 213 chunks
but is tight substrate at scale," say that.

**Scope discipline.** `search_decisions` and `decision_stats` stay
cutoff-exempt. `case_status` still reports the token's case/timestep.
Chunking still respects page boundaries — one page per chunk's `page`
metadata, no chunk spanning pages.

## Step 2 — Implementation
Replace `vectors.npy` + the cosine scan with a Chroma collection per case
(or one collection with a `case_id` metadata filter — decide and record;
per-case is closer to today's shape and keeps the filter simple).

Metadata per chunk: `case_id`, `page`, `file`, `chunk_idx`. The `where`
clause carries the cutoff. Embeddings stay MiniLM at the pinned revision —
**do not let Chroma's default embedding function silently substitute one**;
pass embeddings explicitly or configure the function to the pinned model,
and assert the model identity in a test.

Ingestion keeps its current shape: clone or fetch from Forgejo, chunk,
embed, persist, fingerprint. The **corpus fingerprint** (repo SHAs + model
revisioning params) still gates rebuild-vs-reuse on restart — plus
now a Chroma schema/version component, since a Chroma upgrade that changes
the on-disk format must force a rebuild rather than silently failing.

`/health` keeps its contract: `state`, the per-case census, the
fingerprint. Add whatever Chroma identity belongs there (collection count,
version) — an operator should be able to tell which backend is live.
