# CP-26 — M8b: the stranger test

You are executing CP-26 of `gsj-harness-rollout-server`. CP-25 built a
consumer surface. This puts it in front of someone who wasn't here.

**The deliverable is the friction list, not a green run.** A run that
works while a stranger flounders is a failure; a run that breaks with
every break diagnosed is a success. The predecessor's F-01 through F-22
came from exactly this exercise and were the most valuable findings in
that project.

**Needs GPU and estate.**

## The posture — read this twice
You are the stranger. Adopt it literally:

- **`RUNBOOK.md` and the example project are your only inputs.** Not the
  charter, not the reports, not `staging/`, not this repo's `docs/`
  beyond what the run book links.
- **A fresh environment**: a new directory, a new venv, no reused
  scratch, no `~/cp21` leftovers, no venv that already has the wheel.
  The one thing you may inherit is the *estate services* (Forgejo, MCP,
  the serving engine) — a stranger would be handed tand standing
  them up is item (c) on CP-25's list, tested separately if at all.
- **When you get stuck, write it down before you fix it.** The
  instinct to reach for knowledge you have and the run book doesn't is
  the thing this CP exists to detect. Every time you use out-of-band
  knowledge, that is a finding: what you knew, where it should have
  been written, and what a real stranger would have done instead.
- **Do not improve the docs while running.** Log, finish, then fix.
  Fixing mid-run destroys the measurement.

## Step 2 — Install, as written
`bash install.sh`, exactly as the run book says. Record: what it did,

## Step 3 — Configure, as written
Fill in the six required values from the run book alone. Record every

Then: does `load_config` accept it? Do the renders produce a valid
`TaskRequest` and topology? If a value is wrong, does the error tell you
what to do — or does it name a pydantic field and stop?

## Step 4 — Run
`python train.py` againste. Expect it to be slow and expect
refusals — CP-09′ measured ~19 attempts per qualifying episode and CP-21

Record: whether the run book's stated expectations matched reality, where

**A failing run is an acceptable outcome** if the failure is diagnosed.
Do not fix the library to make it pass — a `gsj_rollout/` change is a

## Step 5 — The findings
One numbered list, in the predecessor's F-NN style, each with: what
happened, what a stranger would have done, where the fix belongs (run
book / example / config schema / library / estate), and severity —
**blocking** (a stranger cannot proceed), **costly** (they proceed but
lose time or trust), or **cosmetic**.

Be specific. "The docs are unclear" is not a finding; "the run book says
`serving_base_url` without `/v1` but the error when y it is a
404 from the engine, which reads as a wrong host" is.

## Step 6 — Fix what's cheap, list what isn't
Now, after the run. **Docs and example only** — `RUNBOOK.md`, the example
config, `install.sh`, the README. Every library-shaped fix goes to the
wishlist with its finding number.

State plainly which findings you fixed and which you didn't, and why.
